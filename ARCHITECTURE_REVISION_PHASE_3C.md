# Phase 3C architecture revision — check-in cutoff

The explicit Phase 3C request changes self-service check-in eligibility from the freeze's same-day late-after-end behavior to a scheduled-end cutoff. The selected rule is start minus the configured early allowance through scheduled end, inclusively; later attempts require a reviewed correction or exception. Actual timestamps still come from PostgreSQL `clock_timestamp()` after locks, truncated downward to seconds. Checkout remains unrestricted in duration/day and strictly after check-in. This revision changes eligibility only, not overtime or payable time.

The original ARCHITECTURE.md and migrations remain intact. Its overnight schedules, immutable published slots, future version replacements with explicitly confirmed restoring patterns, same-employee ownership, session snapshots, multiple returns per occurrence, single open session, no actual overlap and scoped operation-key retries remain in force. No new assignment, override or shift-instance table is introduced. Correction integration remains a controlled placeholder for Phase 3D; this phase has no direct administrative timestamp editor or alternate correction system. Calendar/leave workflows are not introduced here; future source-aware excusal must extend the shared occurrence eligibility resolver before those modules become active.
